# 小说工作流任务发现

并行创作多本小说时，工作流状态分散在目录结构里，「下一步做什么」依赖回忆与翻目录，完成后的落位与提交也有流程成本。本篇定义一个任务发现与整理辅助的规则：扫描仓库现状，呈现候选任务，由人选择，协助执行并落位。

## 输入

网络文学仓库的现状即输入，无需额外数据：

- 各小说的阶段目录（`1_母题` 至 `5_定稿`）与 `outline.md`、`index.md`
- 草稿箱（`1_创作日志`、`2_情绪日记`、`3_创作谈`、`4_创作设定`）
- 仓库的 AGENTS.md（编号规范、目录对应关系、包装文案规范）

## 发现规则

以下规则均为判定式，每条由目录状态直接得出：

1. 编号缺口：`outline.md` 规划的编号在各阶段目录均无对应文件，产生「补写第 N 章」任务。
2. 同号取舍：同一编号在同一阶段存在多份不同名稿件，或同一编号在不同阶段属不同故事线，产生「取舍或合并」任务。
3. 阶段落差：同一编号在低阶段有文件、高阶段没有，产生「推进到下一阶段」任务。
4. 草稿箱积压：`1_创作日志` 非空，产生「整理创作日志」任务，按 `creation-log-workflow.md` 执行。
5. 母题待提炼：`2_情绪日记` 存在未归入任何小说 `1_母题` 的条目，产生「提炼母题」任务。
6. 未解问题：`4_创作设定` 各篇「未解的问题」下的条目，产生「讨论并落档」任务。
7. 文案缺口：`index.md` 必填字段（标题、一句话简介、立意）缺失，产生「拟包装文案」任务。

## 选择交互

1. 每轮呈现三到五个任务卡片，卡片包含：任务描述、类型、依据（来自哪条规则的哪个信号）、落位去向。
2. 用户按编号选择；可先按小说过滤再呈现。
3. 工具不替用户决定写作优先级，呈现顺序固定按发现规则顺序，不做权重排序。

## 执行与落位

1. 选中任务后，汇集相关上下文：同编号各阶段稿件、该小说 `1_母题` 与 `index.md`、仓库 AGENTS 对应规范。
2. 产出按章节编号规范与草稿箱对应关系落位；文件命名、目录、提交类型（`docs:` / `chore:`）均按仓库 AGENTS 执行。
3. 提交流程为先子模块后主仓库。

## 非确定性声明

发现规则是判定式的；执行环节的内容生成（写作、文案、整理）为非确定性，产出仅作建议与初稿，一律人工终审。
