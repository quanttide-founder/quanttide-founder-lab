# knowl-searcher：结构化索引与纯 RAG 对照实验

验证「结构存知识，向量管联想，规则做裁决」的分工设想：同一批文件、同一批查询、同一个打分器，只比「先解析成模型单元再索引」（parse-then-index）与「先切块再索引」（chunk-then-index）的差别。

## 内容

| 文件 | 说明 |
|------|------|
| `docs/experiment.md` | 实验设计：命题、假设预注册、三臂 × 两打分器、指标与风险 |
| `src/` | Rust 实现：语料装载、切块、BM25、嵌入、规则融合、指标 |
| `data/queries.json` | 14 条联想查询 + 5 条同义改写，金标为 `assets/` 相对路径 |
| `data/2026-09-27-bm25-results.json` | 首轮词法打分完整结果（逐查询命中明细） |
| `data/2026-09-27-embed-results.json` | 首轮向量打分完整结果 |
| `data/2026-09-27-首轮结果.md` | 实验日志：结果表、发现、退化诊断 |
| `tests/experiment.rs` | 纯函数回归：确定性、坐标切分、融合 |

语料是主仓库 `assets/`，语料边界与类型由工具箱 Rust 包 `quanttide-founder` 的仓库模型决定（path 依赖 `packages/quanttide-founder-toolkit/packages/rust`）；三问路由与证据分级直接调用库函数。

## 运行

```sh
cargo run -- stats                # 语料统计：131 文件 / 406 单元 / 499 块
cargo run -- run --scorer bm25    # 词法臂，离线可跑
cargo run -- run --scorer embed   # 向量臂，需 GLM_API_KEY 或 KNOWL_EMBED_* 环境变量
cargo run -- run --scorer bm25 --verbose   # 附逐查询命中明细
cargo test                        # 11 项回归
```

首轮结论（证据与诊断见 `data/2026-09-27-首轮结果.md`）：

- 同一嵌入器下，结构化索引大幅胜过裸切块（hit@5 0.79 对 0.29）——切块窗口主题混合，稀释语义信号；单元主题纯净，向量才可比
- 本语料上词法强于向量（recall 0.92 对 0.63）：语料小、查询含精确词；向量的同义长尾优势在本轮查询集里没有显现
- 预注册的规则融合权重未达 H2（embed 下 0.63 → 0.30）：归一化后余弦候选分数聚集在高分区，固定 0.30 路由加成淹没基础分；次要收益是改写稳定性 0.20 → 0.38、结构查询 q09 召回 0.33 → 0.67
- 模型坐标 100% 对 0%（H3）：命中直接给出 `emotion:1-19`、`roadmap:24-28` 级别的审计坐标，rag 臂只有 `chunk#2`
