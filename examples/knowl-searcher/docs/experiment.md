# 实验设计：结构化索引与纯 RAG 对照

## 背景与命题

工具箱的工程思路是「结构存知识，向量管联想，规则做裁决」：目录约定与规则文件承载语义，读取时恢复成带证据坐标的模型单元；向量负责联想（语义近邻），规则在出口裁决。

## 设计评审

评审于 2026-09-27 实施前进行，结论是设计可用，但六处需要修正，其中金标一处是阻断项。修正后的执行口径以本节为准。

1. 金标不存在（阻断）：「源日志段」默认已有日记由日志改写而来，实际标注 6 篇全部无同源段，覆盖 0/6，主指标不可计算。改报 n/a，另加 pooling 相关率作非预注册诊断。
2. 样本量 n=6：top-3 命中率分辨率 16.7%，只够流程验证；补自检（每段首句查自身应近 1.0）与随机基线 3/37 ≈ 0.08 两个参照。
3. 规则与指标脱节：报告输出 top-1 分布、τ 触发计数与聚线条数作标定依据；不回调参的承诺不变，标定留下一轮。
4. τ 的量纲：τ₁/τ₂ 是余弦分阈值，词法分无上界，出口规则只在向量臂生效，词法臂 verdict 记 `null`。
5. 查询档不一致：业务用草稿全文、评测用首句，两档都跑（`--query first|full`），判定只用首句档。
6. 泄漏风险：本轮无同源段，泄漏不成立；保留词法对照臂，用它检验「向量补关键词缺口」这一说法。

## 第一轮：索引粒度对照（已做）

同一批文件、同一个打分器，比「先解析成模型单元再索引」（parse-then-index）与「先切块再索引」（chunk-then-index）。

| 臂 | 索引方式 | 命中携带 |
|----|----------|----------|
| rag | 字符滑窗切块 | 路径 + `chunk#序号` |
| idx | 标题行与 `---` 分隔线切单元，超 900 字按段续分 | 路径 + 类型 + 章节标题 + 行区间 + 洞察分级 |

结论：结构化单元优于裸切块（向量搜索下命中大幅领先）；模型坐标 100% 覆盖（H3）。

## 第二轮：情绪日记提醒（当前）

**业务场景**：写作者在写情绪日记草稿，系统调取默认日志里的相关片段提醒。

### 索引

memory 默认日志按 `---` 切会话段，一段 = 一个检索单元：

```
单元 = { path, line_start, line_end, date, text }
向量化 text → 存向量 + 坐标
```

### 查询

```
query = 当前草稿全文（可以很短）
q_vec = embed(query)
score[u] = cosine(q_vec, u.vec)   取 top-k（k=8）
```

草稿短也能跑——向量的联想能力补上关键词匹配的缺口（「这两天又不太顺利」没有可匹配的词）。

### 裁决（规则在出口）

1. **共振下限** τ₁ = 0.55：低于丢弃
2. **重复上限** τ₂ = 0.92：高于标「已写过」不提醒
3. 聚线：段间 cosine > 0.7 归为同一条情绪线，输出「这条情绪你在 9-05、9-16 都写过」

τ₁/τ₂ 预注册，跑完再标定，不回调参。

### 输出

每条提醒带坐标（`path:line_start-line_end`），写作者可回溯核对——这是第一轮 H3（模型坐标）的业务落地。

### 评判

拿已有情绪日记倒查：每篇日记的**首句**当查询，看它的源日志段排第几。

**指标：源段 top-3 命中率**（单一指标，不搞 hit@5/recall@5）。

实施时发现该指标因金标覆盖 0/6 不可计算，详见「第二轮结果」。

### 后续工作流搜索任务

| 工作流里的搜索 | 真正要测的 |
|---|---|
| journal-to-insight 合并前找重复洞察 | 合并的准确率 |
| fiction 提炼时找相似素材 | 提炼结果可用性 |
| 引用/核对时找出处 | 坐标精确度 |

## 第二轮实施

实现集中在 `src/emotion.rs`：切分复用 `corpus::build_units`（`---` 分隔线，超 900 字续分），规则与评测都是纯函数，`tests/emotion.rs` 九项回归用内存夹具。中间数据一律 JSON，程序不读写文档：

| 文件 | 作用 |
|:--|:--|
| `data/segments.json` | 37 个日志段清单，含 id、行区间、日期、正文，是标注依据 |
| `data/emotion-gold.json` | 同源金标与标注理由 |
| `data/emotion-related.json` | pooling 相关性标注（事后诊断） |
| `data/emotion-results-embed.json` | 向量臂结果（首句档） |
| `data/emotion-results-embed-full.json` | 向量臂全文档辅助档 |
| `data/emotion-results-bm25.json` | 词法诊断臂结果 |

```sh
cargo run -- segments                       # 重建段清单
cargo run -- emotion --scorer embed         # 向量臂
cargo run -- emotion --scorer bm25          # 词法诊断臂
cargo run -- emotion --scorer embed --query full   # 草稿全文辅助档
cargo test                                  # 纯函数回归
```

## 第二轮结果

跑于 2026-09-27，语料 37 段、查询 6 条、检索 top-8、判定 top-3，模型为 embedding-3。

| 臂 | 源段 top-3 | 相关率 P@3 | 自检 | 出口规则 |
|:--|:--|:--|:--|:--|
| embed（首句档，主档） | n/a（金标覆盖 0/6） | 0.11（2/18） | 1.00 | τ₁ 通过 7/48，τ₂ 0，聚线 0 条 |
| embed（草稿全文档，辅助） | n/a | 0.22（4/18） | 1.00 | τ₁ 通过 6/48，τ₂ 0，聚线 0 条 |
| bm25（诊断） | n/a | 0.11（2/18） | 1.00 | 不适用 |

查询档的影响大于打分器：草稿全文档的相关率是首句档的两倍，而向量与词法在首句档打平。业务侧本来就是拿草稿全文去查，这支持下一轮把全文档升为预注册主档；本轮判定仍按预注册只用首句档。

两臂 top-3 的 Jaccard 只有 0.09，结果几乎不同，相关率却相同，都略高于池内密度 5/84 ≈ 0.06——「向量补上关键词缺口」在本轮没有换来可测的收益。

出口规则拿到的是标定依据而非结论：top-1 余弦分落在 0.477–0.605，τ₁ = 0.55 只放行 7/48 对，6 篇里 3 篇整篇无提醒；τ₂ 全程未触发，说明短查询测不出「已写过」，要拿接近原日志的草稿才测得到；通过 τ₁ 的提醒集合内没有任何一对段间 cosine 超过 0.7，聚线为空，0.7 同样需要重标。

主指标下一步二选一：把 pooling 相关性标注升为主指标（标注已就位，口径比同源宽），或构造带来源的查询——从日志改写出日记草稿，同源金标才存在。
