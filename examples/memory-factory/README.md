# memory-factory

用已经写好的个人档案回头扫旧日志，把当时没写进档案的东西捞出来、补回去。

## 要解决的问题

档案是从日志里提炼出来的（蒸馏）。提炼必有损失——日志里很多细节在提炼时没被归位，之后也不会自己回来。

这个程序反过来走：拿档案当索引重扫日志，找出「日志里有、档案里没有」的部分，给出去向建议。

## 它读写的两样东西

**日志**在 `quanttide-founder/assets/memory/`。当天写的直接放在记忆集根部（如 `default/2026-10-05.md`），更早的平铺在 `default/journal/2026-09-27.md`。一篇日志里话题转换处用 `---` 分隔，一段就是一个语义单元。

**档案**在同一仓库的 `assets/memory/default/profile/` 下，五轴：`emotions`（情绪）、`values`（价值观）、`triggers`（触发点）、`methods`（方法论）、`expressions`（表达）。档案是从全部日志里蒸馏出的稳定特征，只描述特征、不给建议。

现有的四道蒸馏都是**正向**的——日志产出档案、路线图、洞察、意图（规则在 `assets/memory/.agents/skills/journal-to-*`）。本案例是**反向**的那一道。

## 一个例子

> 日志（09-28）：「今天参加一个行业聚会，其实聊出了两个客户。」
> 档案：「解决实际问题优于精英社交。」

这两句对不上——不是漏掉的补充，是**方向相反**。程序不该把它塞进档案抹平，而该标记出来待观察。这是本案例最要紧的一条判据。

## 交付方式

与操作者的约定。前四条管本案例交出什么，后两条管人机之间怎么走。

**一、交给操作者的东西只有四类**

| 交付物 | 位置 | 形态 |
|:--|:--|:--|
| 规格 | `docs/` | 可执行的规则——做什么、判据、步骤、验收 |
| 假设 | `docs/assumption.md` | 程序立在什么假设上，哪一层不成立 |
| 数据 | `data/` | JSON，程序之间流转 |
| 报告 | `data/report/<日期>-<描述>.md` | 人读的碎片报告与验收结果 |

**二、程序不碰档案。** 只读日志与档案，产出报告；档案的每次改动由操作者确认后写入。程序不自动改档案，也不写 `docs/`。

**三、人读的一律纯文本。** 报告、标注任务、验收结果一律 Markdown 或 JSONL，能在编辑器里直接看与改——不塞二进制，不塞数据库，是压缩件就解开。

**报告以「新实习生能看懂」为标准。** 报告是操作者主要读的东西，它得自己站得住：

- 结论先说，过程后置——只看前几行就知道这轮成不成
- 术语第一次出现要说清是什么；给数字必给分母
- 给「输入 → 输出」的实例，不只讲规则
- 结论可复核：读者照着报告里的路径与命令能自己走一遍
- 四段结构：意图 → 结果 → 边界 → 下一步，细节只作支撑

**四、分工线。** 机器判机械正确性（分块、匹配、聚类、判型），操作者判意义（认不认、值不值、矛盾保留了没有）。

**五、协作节奏。** 判据定完就静默做完，只在出结果时报一行；低风险的执行决定自行处理；动到判据、结构或档案先问。

**六、一次完备。** 交付在第一次就完整——含入口、含怎么跑、含怎么核。
