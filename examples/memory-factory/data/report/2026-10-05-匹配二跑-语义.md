## 结论

**三栏全对 18/20 = 90.0%，过了 80% 目标线——语义路线成立。** 首跑纯词法是 7/20 = 35.0%，换语言模型逐块判两问后提升 55 个百分点。最要紧的一格「方向」从 8/20 升到 19/20：62 段里判「相反」的从首跑的 48 段降到 **0 段**，与金标（20 块里 0 块相反）一致——稀有事件不再被当成多数事件。62 段全部判定成功，失败 0。

先说清三个词：

- **语义判定**：不再数词、配阈值，把碎片全文和档案条目全文一起交给语言模型，让它按写死的判据直接回答。
- **判断链两问**：① 档案里有没有与这块讲同一件事的条目（没有 → 全新信号）；② 有则碎片方向与条目是 一致 / 相反 / 哪种例外。
- **例外**：块与条目同向、但块是条目的反例场景（例：条目「带人必须有商业收益」对块「这次带人没收益但学到了东西」）。它不算相反，单独一类——判据出自 `docs/assumption.md`「方向相反」那段。

## 二、结果

### 规则（一句话）

## 三、边界

1. **同源风险照单记下**：金标由 AI（Hermes）标，判定由 AI（mimo-v2.6-pro）做，prompt 也由 AI 写——90% 这个数可能偏高，`docs/criteria.md` 要求的人工抽检 5 块仍欠着。首跑 35% 时抬分嫌疑不成立，本轮过了目标线，抽检更有必要。
2. **「相反」「例外」分支本轮没被测到**：金标 20 块里 0 块相反，模型 62 段里也判 0 块相反——数字对得上，但这是「没犯错」，不是「证明会判」。矛盾保留率要验，仍需 TODO 第 7 条的定向样本（已知两处矛盾见 `docs/assumption.md`）。
3. **「无 → 有」仍是最松的一格**：首跑 4 个错块全是这个方向，本轮剩 1 个（`10-03#3`）。与首跑不同，这轮没有阈值可标定——第一问整个交给了模型，「标定方法写进预注册」这条随之落空；要再压只能改判据措辞，那要另起一轮。
4. **条目栏的 1 个错是多成分长块的归属**：`10-04#7` 块里同时有「掌控感」（信心的底色）和「天天输出的积累」（积累感）两种成分，模型与金标各选一条。金标单选本身也压掉了块内其他成分，这类块两侧都可能有更好的选法。
5. **跑后修订（如实记录）**：首趟全量跑完有块记了「失败」，错误原文全是同一件事——模型引用 `###` 子条目标签（如 `methods.md「从实验室到平台」`），解析层却只认 `##` 标签；而金标比对本来就把子条目归一到 `##`，口径不一致。修订只动解析归一层（子条目 → 所属 `##`、截去 `」` 后附注），已在 `src/match.py` 文件头注明，之后只重跑失败块，全部成功。**prompt、模型、max_tokens、重试次数、比对口径未动。**

   **Hermes 验收对此处的更正**：原写「5 个块均不在金标 20 块内」不实。按结果文件里的 `尝试次数` 字段，首试未过的实为 **6 块**，其中 **2 块是金标块**：`2026-09-22.md#2`（尝试 3 次）与 `2026-09-28.md#1`（尝试 2 次）。这两块的最终判定分别是「是 / emotions.md「失控与重新掌控」/ 一致」与「否 / — / —」，**与金标一致**，所以 18/20 不受影响。但修订前的输出没有留档，**无法复算修订前后的差异**——这是记录缺陷：改管线之前应先存一份当时的输出。

6. **比对口径里有一处折算**：模型可判三值（一致 / 相反 / 例外），金标只有两值（一致 / 相反）。按预注册，模型判「例外」时按金标口径折算为「一致」（例外＝同向）。本轮实际判「例外」0 块，这条折算没有用到。
7. **重试情况**：62 块里 56 块首试即成，6 块经第 2 / 3 试成功；失败块的错误原文全部是标签写法不合约束，没有出现过「空回答」。首试 `max_tokens=3000` 全程够用，冒烟时担心的「思考吃光预算返回空 content」没有发生。
