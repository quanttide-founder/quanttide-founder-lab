# 意图

## 一句话

**把已经显性化的认知系统化。**

日志 → 档案这一步（显性化）已经做完。现在要做的，是让档案从一个静态清单，长成能推理、能生成、能自我更新的系统。

## 反向蒸馏在这个目标下的位置

它**不是产品，是一次压力测试**：测档案作为系统，能不能覆盖它自己的来源。捞碎片、标矛盾都是手段——目的是看这张网有没有破洞。

所以「把碎片补回档案」不是目标，那是往回走。

## 走到哪一层

| 层 | 状态 | 说明 |
|:--|:--|:--|
| 显性化 | 已完成 | 日志 → 档案 |
| 结构化 | **卡在这** | 24 条条目彼此没有关系，是清单不是网络 |
| 可操作 | 部分 | 判得了「这块日志档案里有没有」（有无对应 19/20、方向 19/20），但只能查询与匹配，不能推理、不能生成 |
| 自生长 | 未开始 | 差集识别得出来，但差集怎么进档案、进哪里、以什么形态、谁来确认，这条链路没有 |

## 卡点的证据

一次匹配实验里，有一块日志同时挂着两个条目的成分（「掌控感」对「积累感」），模型与人工金标**各选了一条**——条目之间没有定义关系，所以只能单选。这就是「清单」与「网」的差别。

而档案里其实**已经写着关系**，只是没被当成关系：`triggers.md` 开头写「触发后的感受见 `emotions.md`」，`expressions.md` 开头写「观点见 `values.md`、分析模型见 `methods.md`」，`methods.md` 每条都带「适用条件」。把这些已有的指向与归属显性化，比先立一套关系类型学再去套语料更稳。

## 边界

- **程序不碰档案**：只读日志与档案、产出报告；档案每次改动由人确认后写入。
- **同一记忆集内闭环**：某集的日志只与该集的档案比对，不跨集搬运。
- **判定与金标之间要有一环是人**：AI 标金标、AI 做判定、AI 写 prompt 时，准确率这个数有同源风险。
