# 规格

## 它做什么

用档案当查询索引回扫日志，找出「档案没覆盖但日志里存在」的碎片，给出整合建议。

核心是一次差集：

```
日志全集 − 档案已覆盖的部分 = 未整合碎片
```

与普通日志分析的区别：普通分析从日志归纳主题（无先验），本程序用已有主题去日志里找遗漏（有先验，做差集）。

## 匹配：一条判断链，不是两个维度

匹配不是「覆盖度 × 关系」的二维组合，顺序判断即可：

**第一问：档案里有没有对应条目？** 没有 → **全新信号**（新增候选）；有 → 进第二问。

**第二问：碎片的方向与条目一致吗？** 一致——复述则忽略、补充则补进；相反 → **标记为矛盾待观察**。

判据只有一条要写死：**什么算「方向相反」**——碎片的核心主张与条目互斥（档案说「解决实际问题优于精英社交」，日志写一次行业聚会聊出了两个客户）。定义见 `docs/assumption.md`。

原稿的「部分覆盖」一档已砍掉。它曾是口径漂移的来源——同一场景严格讲没被覆盖、宽松讲完全被覆盖。问题不在这一档调得准不准，而在它把一条模糊线变成了两条；判断链只留「有没有对应条目」与「方向一致不一致」两问，「部分覆盖」由第一问吸收。

## 碎片类型

五类碎片都是判断链的产物（新增候选来自第一问的「没有」；深化、重分类、例外、连接来自第二问）：

- **新增候选**：档案完全没提的新信号（反复出现的「对团队节奏的不耐烦」）
- **深化候选**：档案提了但没展开的弱信号（「信心的底色」只有一句，日志里全是具体场景）
- **重分类候选**：档案里归错类（被归到「规模焦虑」，重读更像「失控感」）
- **例外候选**：与档案矛盾的单次记录（档案说精英社交没意思，某篇写它带来了客户）
- **连接候选**：跨条目的关联（「厌倦带人」与「教 AI 收益上升」同段出现，档案里分属两处）

## 步骤

1. **分块**：把日志切成语义单元——不按段落，按「一个完整的情绪 / 触发 / 判断 / 策略」切
2. **匹配**：逐块比档案，标三档（粗筛关键词，精筛语义相似度）
3. **聚类**：把未覆盖与部分覆盖的块聚起来，看是不是在说同一件事
4. **判型**：按上面五类命名
5. **出建议**：不自动改档案，给可确认的建议——含出现次数、相关日志日期、建议归入哪一篇、待确认点

建议的形态（示例）：某信号出现 5 篇，相关日志 09-12 / 09-18 / 09-24 / 10-01 / 10-03，建议归入 `emotions.md` 新增「对协作节奏的焦虑」或归入 `triggers.md` 新增「团队节奏与个人节奏不同步」，待确认它是独立情绪还是「规模焦虑」的子类。

## 最小版本

1. 读日志 → 分块 → 逐块比档案 → 输出「未覆盖块列表」
2. 人看未覆盖块，**手工聚类**
3. 跑一遍，看有没有漏掉的碎片
4. 再决定要不要上 embedding 与 LLM 判型

规模参考：default 集日志 09-05 起约十六篇、两万字，分块后约百级——这个量级手工聚类就够，上聚类算法没有统计意义。

## 复用

分块与两臂检索不重新实现：用实验室 `src/segmentation.py`（切段）与 `src/retrieval.py`（bm25 / embed 两臂），即 `novel-planner` 已在用的那套。
