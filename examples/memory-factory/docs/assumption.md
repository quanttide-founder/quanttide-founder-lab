# 假设

程序立在一条假设上：**碎片能被捞出来、归位、整合进档案**。本文件写作前的 `spec.md` 与 `criteria.md` 都以此为前提。

这条假设**不完全成立**。拆成三层看，每层都有成立条件，也各有失败点。

## 一、碎片可整合

**假设**：日志里没被整合的碎片，可以被捞出来、归位、整合进档案。

**成立条件**：碎片之间确有内在关联，不是随机噪音。

**失败点**：有些碎片没被整合，不是「当时没注意」，而是它**与现有档案不兼容**。档案说「精英社交没意思」，某篇日志写一次社交有收获——这不是漏掉的碎片，是**矛盾信号**。强行整合会破坏档案一致性。

## 二、整合后能形成内在一致性

**假设**：碎片归位后，档案更完整、更一致。

**成立条件**：档案有一个稳定的核心，碎片是围绕核心的补充。

**失败点**：人的认知未必是「一个核心 + 补充」，也可能是**多个互相冲突的子人格**——一个想缩小窗口、专注业务，另一个想铺大摊子、展示想法。两个都是本人，但不一致。强行整合成一个内在一致的档案，等于抹掉其中一个人格：那是失真，不是提炼。

## 三、一致性是目标

**假设**：程序的目标是让档案内在一致。

**成立条件**：一致性对本人有用。

**失败点**：一致性不一定是最高价值。矛盾本身是信号——说明在两个方向之间拉扯；拉扯可能才是真相，而不是「最终选一个」。过早一致会失去探索空间。

**实证**：档案里的「规模焦虑」写着「摊子没铺完」与「范围过大」**同时成立**——一个被保留的矛盾，没有被整合成「其实我该缩小」；「深层的恐惧仍在」也与「整体轨迹向好」的叙述相矛盾，但它被留了下来。

**结论**：档案已经在做一件事——**允许不一致存在**。

## 修正后的假设

**碎片可以被识别、归类，并区分为「可整合」「矛盾待观察」「独立新信号」三类。**

| 类型 | 处理 | 例子 |
|:--|:--|:--|
| 可整合 | 补进档案对应条目 | 「深层恐惧」的具体对象 |
| 矛盾待观察 | 标记，不强行整合，定期回看 | 精英社交的例外 |
| 独立新信号 | 新增条目，或暂存待定区 | 对团队节奏的不耐烦 |

程序的目标因此不是「让档案一致」，而是**让档案更完整地反映本人，包括本人的不一致**。

一致性是读完之后的感受，不是整合时的标准。

## 对设计的影响

**匹配**：一条判断链，两问——档案里有没有对应条目（没有 → 全新信号）；有的话，碎片方向与条目一致吗（一致：复述忽略、补充补进；相反：标记待观察）。

判据只有一条要写死：**方向相反**。定义在 2026-10-05 首跑后重写过一次——首跑证明词法填不了这个空缺（细节见 `docs/criteria.md` 四）。

**方向相反**：块的核心主张与条目的核心主张**互斥**，即两者不能同时为真。

- **一致**（含复述、补充、具体化）：块复述条目 → 忽略；块补充条目 → 补进；块是条目的具体场景 → 补进
- **相反**：条目说 A，块说非 A，且 A 与非 A 不能同时成立。例：条目「精英社交没意思」对块「一次行业聚会聊出了两个客户」
- **例外**（不是相反，单独一类）：块与条目同向，但块是条目的反例场景。例：条目「带人必须有商业收益」对块「这次带人没收益但学到了东西」→ 标记为「例外」，不改条目

判定要求：

- 需要语义理解，**不能靠词面极性**
- 词面极性不同 ≠ 语义相反（首跑 09-26：「数字资产定价」对「不留下资产的活动」）
- 否定词出现 ≠ 语义相反（首跑 09-20：「**非常**积极」）
- ±3 字观察窗内的否定词，不构成判据

**由此推出**：纯词法不能承担「方向相反」——这条判据要的是「两个主张能不能同时为真」，而词法只看得见「否定词出现了没有」。

原稿的「已覆盖 / 部分覆盖 / 未覆盖」与「兼容 / 矛盾 / 无对应」不是两个正交维度（**矛盾必然预设档案里有对应条目**），收成上面的链；「部分覆盖」一档随之砍掉。

**待观察区**：矛盾碎片不并入档案条目正文，方向是**独立待观察清单 + 档案条目里留一行指针**。清单与五轴并列放在 `profile/` 下，文件名 `contradictions.md`，`## ` 一条记一个矛盾对象——和档案同一种形态，不引入 YAML。

一条记录只记事实：矛盾对象叫什么、双方各是什么主张、各出自哪里（档案条目或日志日期）、出现过几次、现在什么状态。不写「该选哪边」、不写处理办法——记忆仓库的明规矩「档案只描述特征、不给建议」在待观察区照样成立：清单陈述的是「矛盾存在且未消解」这个特征，指针陈述的是「本条在清单里有对应记录」，都是描述。矛盾留着还是归一边，由操作者看日志判断。

档案里现成的两处，各套一遍：

- **「规模焦虑」**：主张甲「摊子还没铺完、想法还没展示出来」，主张乙「范围已经过大，超出注意力范围」，在 `emotions.md`「规模焦虑」与 `triggers.md`「范围失控」里同时成立。套法：清单一条记录「摊子没铺完 vs 范围过大」，两个条目末尾各加一行指针。
- **「信心的底色」**：主张甲「深层的恐惧仍在」，主张乙「整体轨迹向好」，同在 `emotions.md`「信心的底色」一条之内。套法：清单一条记录「深层的恐惧仍在 vs 整体轨迹向好」，该条目末尾加一行指针。双方在同一条目内不妨碍——清单记的是矛盾本身，不看它散在几处。

两处条目正文都不动：档案现在就把两主张并存着，这是它允许不一致的做法；清单与指针是旁边的索引，不把矛盾搬进也不搬出条目。指针的形态（加在条目末尾）：

> 矛盾待观察：见待观察清单「摊子没铺完 vs 范围过大」。

**聚类**：三类碎片各有聚类键——兼容按目标档案条目，矛盾按矛盾对象，全新信号按语义相似度。矛盾单独聚，不与兼容碎片混。否则会把「精英社交有用」与「精英社交没意思」聚成一类，得出错误结论。

**整合建议**：分三种输出，落点各不同——补进（可整合 → 对应条目正文）；标记（矛盾 → 待观察清单加一条记录，对应条目末尾加一行指针）；新增（独立信号 → 五轴对应文件新增条目，归不了轴的进待定区）。

**验收**：加一条判据——**程序有没有保留矛盾，而不是抹平矛盾**。把所有碎片整合成「一致」是失败；把矛盾单独标出来才是成功。

## 一句话

关键假设不是「碎片可以被整合成内在一致」，而是「碎片可以被识别、归类，并区分为可整合、矛盾待观察、独立新信号」。**一致性是副产品，不是标准。**
