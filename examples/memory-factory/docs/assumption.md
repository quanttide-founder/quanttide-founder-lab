# 假设

程序立在一条假设上：**碎片能被捞出来、归位、整合进档案**。本文件写作前的 `spec.md` 与 `criteria.md` 都以此为前提。

这条假设**不完全成立**。拆成三层看，每层都有成立条件，也各有失败点。

## 一、碎片可整合

**假设**：日志里没被整合的碎片，可以被捞出来、归位、整合进档案。

**成立条件**：碎片之间确有内在关联，不是随机噪音。

**失败点**：有些碎片没被整合，不是「当时没注意」，而是它**与现有档案不兼容**。档案说「精英社交没意思」，某篇日志写一次社交有收获——这不是漏掉的碎片，是**矛盾信号**。强行整合会破坏档案一致性。

## 二、整合后能形成内在一致性

**假设**：碎片归位后，档案更完整、更一致。

**成立条件**：档案有一个稳定的核心，碎片是围绕核心的补充。

**失败点**：人的认知未必是「一个核心 + 补充」，也可能是**多个互相冲突的子人格**——一个想缩小窗口、专注业务，另一个想铺大摊子、展示想法。两个都是本人，但不一致。强行整合成一个内在一致的档案，等于抹掉其中一个人格：那是失真，不是提炼。

## 三、一致性是目标

**假设**：程序的目标是让档案内在一致。

**成立条件**：一致性对本人有用。

**失败点**：一致性不一定是最高价值。矛盾本身是信号——说明在两个方向之间拉扯；拉扯可能才是真相，而不是「最终选一个」。过早一致会失去探索空间。

**实证**：档案里的「规模焦虑」写着「摊子没铺完」与「范围过大」**同时成立**——一个被保留的矛盾，没有被整合成「其实我该缩小」；「深层的恐惧仍在」也与「整体轨迹向好」的叙述相矛盾，但它被留了下来。

**结论**：档案已经在做一件事——**允许不一致存在**。

## 修正后的假设

**碎片可以被识别、归类，并区分为「可整合」「矛盾待观察」「独立新信号」三类。**

| 类型 | 处理 | 例子 |
|:--|:--|:--|
| 可整合 | 补进档案对应条目 | 「深层恐惧」的具体对象 |
| 矛盾待观察 | 标记，不强行整合，定期回看 | 精英社交的例外 |
| 独立新信号 | 新增条目，或暂存待定区 | 对团队节奏的不耐烦 |

程序的目标因此不是「让档案一致」，而是**让档案更完整地反映本人，包括本人的不一致**。

一致性是读完之后的感受，不是整合时的标准。

## 对设计的影响

**匹配**：不只判「已覆盖 / 未覆盖」，还要判碎片与档案条目的关系——**兼容**（一致，可整合）、**矛盾**（冲突，需标记）、**无关**（全新信号，档案无对应）。

**聚类**：矛盾碎片单独聚，不与兼容碎片混。否则会把「精英社交有用」与「精英社交没意思」聚成一类，得出错误结论。

**整合建议**：分三种输出——补进（可整合 → 对应条目）、标记（矛盾 → 加「例外」或「待观察」）、新增（独立信号 → 新增条目或进待定区）。

**验收**：加一条判据——**程序有没有保留矛盾，而不是抹平矛盾**。把所有碎片整合成「一致」是失败；把矛盾单独标出来才是成功。

## 一句话

关键假设不是「碎片可以被整合成内在一致」，而是「碎片可以被识别、归类，并区分为可整合、矛盾待观察、独立新信号」。**一致性是副产品，不是标准。**
