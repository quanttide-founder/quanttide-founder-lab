# 实验设计：风格规则库 + 情节账本双库验证

> 本篇是 novel-planner 的第三条能力轨（前两条：联想检索 `searcher.py`、任务看板 `task_board.py`）。
> 它验证「生成前注入双库、生成后回收偏差」能否压低风格/事实/编造三类偏差。
> 旋钮与骨架的边界见文末「验收映射」。

## 1. 实验目标（假设）

- H1：生成前注入情节账本切片，可显著降低事实性偏差。
- H2：生成前注入风格规则，可显著降低风格性偏差。
- H3：两者合流后，整体偏差低于单独使用任一方。
- H4：回流机制能持续降低后续章节的偏差。

## 2. 实验范围

本轮只验证最小可用闭环，不追求完整产品化。

包含：风格规则库（≤12 条启用）、情节账本（事实/欠账/物件位置三类）、
上下文组装（STYLE/STATE/DEBTS/SCENE）、偏差回流、人工标注为主自动化检查为辅。

不包含：多人协作、复杂权限、可视化看板、大规模自动训练、长周期历史迁移。

## 3. 骨架（不可调 — invariant）

以下任一条被动，实验即测不出东西，代码层已加护栏锁定：

1. **四组对照 A/B/C/D 不可少**：A 无规则无账本（基线）、B 仅风格规则（H2）、
   C 仅账本（H1）、D 规则+账本（H3）。少任一组都无法区分两库各自贡献。
2. **上下文组装顺序不可变**：STYLE 全量注入启用规则 → STATE/DEBTS 按章节与关键词切片
   → SCENE 由人工指定本场目标与禁止项。此顺序是假设的一部分。
3. **回流不能跨库**：事实问题不能写成风格规则，审美偏好不能写进账本。破此条即污染实验。
   `dual_library.backflow()` 对「事实写成规则」直接抛错。
4. **启用规则上限 12 条不可破**：破了无法判断是规则无效还是过载。
   `dual_library.enabled_rules()` 超 12 直接抛错。
5. **标注必须在生成后做，不能边生成边改**：否则分不清「模型变好」还是「中途改了规则」。

## 4. 旋钮（可调 — 集中存于 `data/dual-library/config.json`）

改这些只影响成本与精度，不影响实验有效性。

| 旋钮 | 取值 | 调了会怎样 | 第一版默认 |
|---|---|---|---|
| 测试文本章数 | 2–5 章 | 越多账本切片价值越显；太少看不出事实偏差 | 3 章（含「拖鞋」线索） |
| 账本补录密度 | 关键物件 vs 全量 | 越高 C/D 优势越大，补录成本越高 | 只扒：物件位置/人物已知信息/未解欠账 |
| 启用规则数 | 3→8→12 | 越多 B/D 风格改善越显，边际递减 | 3 条兜底 |
| 生成字数 | 400–1200 | 越长越暴露偏差，标注成本线性增 | 600 字 |
| 标注粒度 | 只数次数 vs 逐条摘录 | 前者快粗糙，后者慢但能回流 | 只数次数 |
| 回流轮次 | 1 vs 3 | 越多越能验证 H4 | 1 轮（H4 留第二轮） |
| 场景复杂度 | 纯对话 vs 对话+动作+物件 | 越复杂账本价值越大 | 含对话+物件交互 |
| 评估人 | 自己 vs 加盲评 | 单人快有主观偏差，双人可算一致性 | 自己先做 |

旋钮决策顺序：时间紧→调小文本/减粒度/1 轮；看账本价值→调高复杂度与密度；
看风格价值→加到 8 条规则+风格密集文本；验证 H4→至少 3 轮且其他不变；
人手不够→调小字数/只做 1 个场景四组对照。

## 5. 数据准备

### 5.1 风格规则库 `rules.json`
每条字段：`rule_id` `instruction` `type`(禁用/句法/参考) `status`(观察/启用/淘汰)
`source` `hit_count`。

### 5.2 情节账本 `ledger.json`
每条字段：`entry_id` `type`(fact/debt/inventory) `chapter_id` `content`
`resolved` `tags`。初始从测试文本回溯补录：≥10 事实、≥5 欠账、≥5 物件位置。

### 5.3 测试文本
`data/dual-library/source/` 下放 3 章原文（含「拖鞋」线索、物件、人物关系、
信息不对称，并预埋若干风格问题如心理标签/总结比喻/汇报式台词）。

本地 loader（`src/loader.py`）读取该 markdown：按 `# 第N章` / `## 章名` 切章
（编号 c1/c2/…），并解析任意位置的账本条（格式 `- [type][chapter] 内容`，
type ∈ fact/debt/inventory）。回填命令：

```
python3 examples/novel-planner/src/planner.py ledger --backfill
```

按 content 去重，已存在的跳过；账本条与章节分离存储，互不污染。

## 6. 分组与组装

四组生成同一场景续写（600–800 字）。组装格式固定：

```
【STYLE】{enabled_rules 全量}
【STATE】{relevant_facts 按章节/关键词过滤}
【DEBTS】{unresolved_debts}
【SCENE】{scene_goal}{scene_constraints}
```

## 7. 偏差标注与回流

标注三类：风格偏差（心理标签/总结比喻/汇报台词/其他违例）、事实偏差
（与账本冲突/物件位置错/人物已知信息错/时间线矛盾）、编造偏差
（新增未确认设定/擅自补全欠账/引入未出现人物物件）。

回流规则：规则命中→`hit_count+1`；未覆盖→新增`观察`候选规则（**不自动启用**）；
账本未喂入→补录事实/物件位置；编造→进**待确认池**不直接入库。严禁事实写成规则。

## 8. 评估指标

主要：每千字风格/事实/编造偏差数、总偏差数、规则命中率、账本命中率。
次要：新增观察规则数、淘汰数、补录条目数、标注耗时。

## 9. 通过标准

B 风格偏差显著低于 A；C 事实偏差显著低于 A；D 总偏差低于 A/B/C 中至少两组；
回流后下一轮偏差未上升；启用规则 ≤12；账本能正确按章节过滤；无事实被误写入规则库。

## 10. 执行步骤

1. 初始化规则库/账本表结构 → 2. 导入 3 条兜底规则 → 3. 导入测试文本 →
4. 补录初始账本 → 5. 生成 A → 6. 生成 B → 7. 生成 C → 8. 生成 D →
9. 收集四组 → 10. 人工标注 → 11. 算指标 → 12. 回流 → 13. 用更新库再跑 D → 14. 出报告。

## 11. 输出产物

四组生成文本、偏差标注表、指标对比表、更新后规则库、更新后账本、结论、改进建议。

## 12. 约束（不自动）

不自动启用观察规则；不自动删除启用规则；不自动把事实写入风格规则库；
不自动把审美判断写入账本；每次生成必须记录完整上下文快照；所有变更必须可追溯。

## 13. 验收映射

- **骨架（本篇 §3）** = 不可调验收规格，由 `src/dual_library.py` 的护栏（12 上限、不跨库、四组齐全）强制。
- **旋钮** = `data/dual-library/config.json`，调它不触碰本篇。
- 代码不读写文档；中间数据一律 JSON；回归测试锁定组装、过滤、护栏与指标。
