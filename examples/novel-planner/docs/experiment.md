# 实验设计：结构化索引与纯 RAG 对照

> 合并说明：本实验原为独立实验 `knowl-searcher`（Rust），已并入[小说策划助手](../README.md)（`examples/novel-planner/`，Python）。下文命令以合并后的 CLI 为准；第一轮「索引粒度对照」的实现随 Rust 版下线，设计与结果仍记录在本篇。

## 背景与命题

工具箱的工程思路是「结构存知识，向量管联想，规则做裁决」：目录约定与规则文件承载语义，读取时恢复成带证据坐标的模型单元；向量负责联想（语义近邻），规则在出口裁决。

## 设计评审

评审于 2026-09-27 实施前后分两轮进行，结论是命题本身要改。修正后的执行口径以本节为准。

1. 命题错位（阻断，已重设计）：原设计把实验当溯源——拿日记首句找「源日志段」。日记是加工产物，原始日志是随手写的，两者是联想关系，不存在逐段出处；标注 6 篇全部无同源段。改为问「捞出来的片段有没有用」，主指标换成 top-3 相关率。
2. 样本量 n=6：相关率分辨率 16.7%，只作流程与方向验证，不作统计推断；补自检（每段首句查自身应近 1.0）与随机基线 3/段数 两个参照。
3. 规则与指标脱节：报告输出 top-1 分布、τ 触发计数与聚线条数作标定依据；不回调参的承诺不变，标定留下一轮。
4. τ 的量纲：τ₁/τ₂ 是余弦分阈值，词法分无上界，出口规则只在向量臂生效，词法臂 verdict 记 `null`。
5. 查询档：业务用草稿全文、原设计用首句，本轮判定改用全文档，`--query first` 保留作对照。
6. 泄漏风险：无同源段，字面改写泄漏不成立；保留词法对照臂，用它检验「向量补关键词缺口」这一说法。

## 第一轮：索引粒度对照（已做）

同一批文件、同一个打分器，比「先解析成模型单元再索引」（parse-then-index）与「先切块再索引」（chunk-then-index）。

| 臂 | 索引方式 | 命中携带 |
|----|----------|----------|
| rag | 字符滑窗切块 | 路径 + `chunk#序号` |
| idx | 标题行与 `---` 分隔线切单元，超 900 字按段续分 | 路径 + 类型 + 章节标题 + 行区间 + 洞察分级 |

结论：结构化单元优于裸切块（向量搜索下命中大幅领先）；模型坐标 100% 覆盖（H3）。

## 第二轮：情绪日记联想（当前）

**业务场景**：写作者把一段体验加工成情绪日记时，系统从 memory 的原始日志里捞出相关片段提醒。日记是加工出来的，原始日志是随手写的，两者是联想关系而不是出处关系。

### 索引

memory 各集原始日志（default / fiction，共 51 段）按 `---` 切会话段，一段 = 一个检索单元：

```
单元 = { path, line_start, line_end, date, text }
向量化 text → 存向量 + 坐标
```

### 查询

```
query = 情绪日记全文（草稿代理）
score[u] = max( cosine(分块(query), 分块(u)) )   取 top-k（k=8）
```

文本按 480 字分块嵌入，长查询与长段都取分块最大相似度，不吃截断亏。查询集是观察站的 6 篇情绪日记；灵感与场景后续轮次再接，先控制标注量。

### 裁决（规则在出口）

1. **共振下限** τ₁ = 0.55：低于丢弃
2. **重复上限** τ₂ = 0.92：高于标「已写过」不提醒
3. 聚线：段间 cosine > 0.7 归为同一条情绪线，输出「这条情绪你在 9-05、9-16 都写过」

τ₁/τ₂ 预注册，跑完再标定，不回调参。

### 输出

每条提醒带坐标（`path:line_start-line_end`），写作者可回溯核对——这是第一轮 H3（模型坐标）的业务落地。

### 评判

情绪日记与原始日志之间没有逐段出处，所以金标不问出处，只问有用。

```
金标 = 相关性标注：该段能否为写这篇日记的人提供提醒价值，即同一次经历、
       同一具体事实、同一场景细节，或同一情绪处境下可接话的具体内容；
       仅词汇重合、泛泛同主题判不相关
标注 = pooling：两臂候选并集逐段判断，单标注者（AI 标注，作者抽查）
指标 = top-3 相关率 = 相关段数 / (3 × 查询数)，单一指标
参照 = 自检（每段首句查自身）、随机基线 3/段数、池内相关密度
```

τ 仍预注册，跑完标定不回调参。

## 第二轮实施

实现集中在 `searcher.py`：切分复用 `build_units`（`---` 分隔线，超 900 字续分），规则与评测都是纯函数，`tests/test_searcher.py` 十五项回归用内存夹具（另有一项锁定与 `data/segments.json` 的语料一致性）。中间数据一律 JSON，程序不读写文档：

| 文件 | 作用 |
|:--|:--|
| `data/segments.json` | 51 个日志段清单，含 id、行区间、日期、正文，是标注依据 |
| `data/pool.json` | 标注候选池：每条查询的两臂候选 id |
| `data/related/diary.json` | pooling 相关性标注（63 个判断，10 个判相关） |
| `data/results-embed.json` | 向量臂结果 |
| `data/results-bm25.json` | 词法对照臂结果 |

```sh
python3 examples/novel-planner/src/planner.py segments                   # 重建段清单
python3 examples/novel-planner/src/planner.py emotion --scorer embed     # 向量臂
python3 examples/novel-planner/src/planner.py emotion --scorer bm25      # 词法对照臂
python3 examples/novel-planner/src/planner.py emotion --query first      # 首句对照档
python3 -m unittest discover -s examples/novel-planner/tests         # 纯函数回归
```

## 第二轮结果

跑于 2026-09-27，语料 51 段、查询 6 篇情绪日记、标注 63 判断（10 个相关）、检索 top-8、判定 top-3，模型 embedding-3。三则使用案例见 [cases.md](./cases.md)。

| 臂 | top-3 相关率 | 至少一条进 top-3 | 自检 | 池内密度 | 随机基线 |
|:--|:--|:--|:--|:--|:--|
| embed（全文档） | 0.28（5/18） | 0.67（4/6） | 0.94 | 0.16 | 0.06 |
| bm25（对照） | 0.17（3/18） | 0.33（2/6） | 1.00 | 0.16 | 0.06 |

向量臂确实补上了词法的缺口：两臂 top-3 的 18 个坑位重叠为 0，相关率 0.28 对 0.17，命中率 0.67 对 0.33；词法臂约等于池内密度 0.16，即没有增益。样本只有 6 条，这是方向性证据，不是统计结论。

排序有用，阈值没用：10 个相关段有 8 个进了 top-8（召回 0.80），但相关段分数中位数 0.500、非相关段 0.489，两堆分不开；τ₁ = 0.55 把 48 对里 40 对丢掉，8 个相关段只剩 2 个过线。τ₂ = 0.92 面对的最高分只有 0.634，永不触发；聚线 0.7 只归出 1 条。

绝对水平还不高：top-3 的 18 个坑位只装进 5 个相关段，够做提示，不够替代检索。

标定留给下一轮：τ₁ 建议降到 0.47 附近，或改成只排序不过滤；τ₂ 与聚线 0.7 在这个模型和查询形态下都需重设。预注册在下一轮跑之前定稿，本轮不改参。
