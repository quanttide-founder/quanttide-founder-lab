# 测试文本（双库实验用）

在此粘贴 **3 章**原文，要求：

- 每章 800–1500 字；
- 包含明确物件（尤其一条「拖鞋」线索）、人物关系、信息不对称；
- 预埋若干风格问题：心理标签、总结比喻、汇报式台词，便于 B/D 组对照。

章节用标题标出（loader 按标题切章，编号 c1/c2/c3…）：

```
# 第一章 玄关的拖鞋
（正文……）

# 第二章 没说出口的疑问
（正文……）

# 第三章 抽屉里的钥匙
（正文……）
```

## 账本补录（loader 自动解析，回填进 ledger.json）

在文件任意位置，用如下格式列出账本条，运行
`python3 examples/novel-planner/src/planner.py ledger --backfill` 即解析回填：

- 格式：`- [type][chapter] 内容`
- type ∈ `fact`（事实）/ `debt`（欠账）/ `inventory`（物件位置）
- chapter 填对应章编号（c1/c2/c3…）

示例（第一版只扒：物件位置 / 人物已知信息 / 未解欠账）：

- [fact][c1] 拖鞋在玄关鞋柜，是旧的一双
- [fact][c2] 男主不知道这双拖鞋是谁买的
- [debt][c1] 谁买了这双拖鞋（未解）
- [inventory][c3] 钥匙放在客厅抽屉第二格

> 占位：尚未粘贴原文与账本条。补录前账本为空，C/D 组无法体现账本价值。
