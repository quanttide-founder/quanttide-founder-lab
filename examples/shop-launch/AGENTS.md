# AGENTS.md

本目录的目的不是存放开店计划，而是**建立一个结构化的分析框架**：把「AI 能参与多少实体决策」拆成可评估、可验证、可迁移的单元。滁州串串店是首例场景，用来实例化框架，不是框架本身。

## 目录定位

| 位置 | 性质 | 内容 |
|------|------|------|
| `AGENTS.md` | 框架的操作说明 | 字段、标尺、判定规则、流程 |
| `docs/` | 框架规格与工具用法 | 维度与规则的正式论述 + 各工具用户文档（assess / review / deviation / ledger）；`AI 辅助开店.md` 为自 memory 迁入的原文，不改 |
| `data/` | 案例实例 | 一个场景一份，按下方字段填写 |
| `src/` | 数据处理工具 | CLI（`ledger.py`，L1 缺失拒绝计算）。人的判断走 Label Studio（见 `TODO.md` Phase 2），不建第三个人机界面 |
| `tests/` | 回归测试 | `present()`、共享数据层与一致性检查，无图形环境可跑 |
| `README.md` | 当前状态 | 现状、下一步、判据 |

## 分析单元

**决策环节**。任何场景先拆成若干决策环节，逐环节评估，不整体打分。

## 字段

| 字段 | 含义 | 取值 |
|------|------|------|
| 环节 | 决策单元 | 名词短语（选址、定价、现场运营…） |
| AI 能力分 | 该环节能交付的质量 | 0–100，见标尺 |
| 局限 | AI 够不着的具体点 | 一句话，须指明缺什么，不写笼统评价 |
| 输入依赖 | 该环节的判断靠什么支撑 | A / B / C，见下 |
| 证据等级 | 结论依据 | L0 / L1 / L2 |
| 验证状态 | 该行结论的当前效力 | 待验证 / 已验证 / 已证伪 |

**输入依赖**（框架的核心轴，分数主要由它决定）：

- **A 抽象推理** — 信息、逻辑、结构。AI 强项，不依赖现场
- **B 本地数据** — 依赖本地锚点、口味、人流等微观事实。**缺数据则弱，喂入 L1 后重评**
- **C 物理在场** — 现场、身体、随机性。AI 不可替代

一个环节可同时命中多类（如 `A+C`）。分数只覆盖其中 AI 能交付的部分；命中 C 时，`局限` 字段必须点名需人工的那部分，不得把 C 的内容算进分数里。

**证据等级**：

- **L0** 通用知识，未喂本地数据 —— 一律视为待验证假设，不是结论
- **L1** 已喂入本地实地数据
- **L2** 已实测验证

## 评分标尺

| 分数 | 处置 |
|------|------|
| ≥ 80 | 直接采纳 |
| 60–79 | 采纳，落地前人工抽验 |
| 31–59 | 仅作参考输入，判断由人补全 |
| 1–30 | 人工独占，AI 不参与 |

**一致性检查**（入库前必过）：

- 纯 A 环节应 ≥ 60；低于此说明评分有误或缺证据
- 含 C 的环节应 ≤ 80，且 `局限` 必须写明 C 部分由谁兜底
- 纯 C 环节应 ≤ 30；高于此说明低估了现场依赖
- B 类必须标出证据等级，L0 的分数在拿到 L1/L2 前不视为最终值

## 字段填写示例

| 环节 | 能力分 | 局限 | 输入依赖 | 证据等级 | 验证状态 |
|------|--------|------|----------|----------|----------|
| 定价 | 40 | 给得出通用模型，但不知道本地已锚定 5 毛/签 | B | L0 | 待验证 |
| 底料 / 供应链 | 60 | 能给采购渠道与选品标准，但闻不到、尝不出 | A + C | L0 | 待验证 |

第二行是混合依赖：分数 60 只覆盖「渠道与选品标准」这部分 A 类能力，`局限` 里点名的感官判断属 C，由人工兜底，不计入分数。

一行必须六字段齐全。缺证据的环节照样填，用 L0 + 待验证标明，不留空。

## 产出

1. **能力对照表** —— 单场景全部环节的字段汇总，落 `data/`（首例：[`data/能力对照表.csv`](data/能力对照表.csv)，由 `src/assess.py --seed` 生成、`check` 把关，用法见 [`docs/assess.md`](docs/assess.md)）
2. **偏差地图** —— 跨场景沉淀，记录每个环节的「预测值 vs 实测值」，得出该环节在该品类 / 该城市的可信度。比单个场景的成败更有复用价值（schema 与用法见 [`docs/deviation.md`](docs/deviation.md)）

```sh
python3 src/assess.py --seed "docs/AI 辅助开店.md" --out data/能力对照表.csv
python3 src/assess.py check data/能力对照表.csv   # 入库前必过，违规退出码 1
```

人工裁决的往返（队列 → Label Studio → 写回）见 [`docs/review.md`](docs/review.md)。

## 测算工具

`src/ledger.py` 把框架中的 A 类环节落成可执行计算：人均拆解、底料摊薄、三阶段达标线与盈亏平衡。

**参数来源三级标注**，与上方字段的证据等级对齐，工具逐行在输出中标出：

- `[锁]` 取自 `data/火锅串串.md`，已由实地数据校准，**不得覆盖**
- `[L0]` 未验证假设（如签型比例 `60:30:10`），必须显式给出
- `[L1]` 待回填。**缺失时拒绝计算该段并打印缺口，不代填数值**；退出码 `2` 表示有缺口

```sh
python3 src/ledger.py selftest          # 12 项固定数学关系自检
python3 src/ledger.py all               # 全部测算，L1 缺口会标出
python3 src/ledger.py stall --daily 149 # 实测回填，判定达标
python3 src/ledger.py shop --staff 8000 --utility 2000 --other-fixed 1000 --food-rate 0.35
python3 src/ledger.py gaps              # 只看待回填项
```

边界：工具只算 A 类。C 类（现场、感官、随机性）的结果不进工具，也不因工具算得出而被视为已验证。

使用说明见 [`docs/ledger.md`](docs/ledger.md)。三层报表：

```sh
python3 src/ledger.py report --mode shop --ticket 32:45 --traffic 15:20 --staff 1200 --utility 800 --food-rate 0.35
python3 -m unittest discover -s tests   # 48 项回归，无图形环境可跑
```

**唯一策略**：缺 L1 不代填、不估算，拒绝计算（退出码 `2`）；数据完整度是结论的可信度指标，估算值不算已填。交互面只有两个：本 CLI 出数据，Label Studio 收人的判断。

## 新增案例

1. `data/` 下建场景文件，拆环节、逐行填字段
2. 过一致性检查，再汇总成能力对照表
3. 实测后回填偏差，把验证状态推进到 L2，同步更新对照表与偏差地图
4. 只改案例数据 → 改 `data/`；要改字段、标尺、判定规则 → 改本文件并在 `README.md` 记一笔

## 硬约束

- 由实地数据校准的案例事实（如本地价格锚点）不被 AI 通用模型覆盖；建议与之冲突时先提示冲突，不静默采纳
- 依赖物理在场才能判定的内容（口味、现场、人流）标注「需人工验证」，不给确定性结论
- 实地才能验证的分数不因论证充分而上调；论证充分只影响 A 类，不改变 B/C 的证据等级
