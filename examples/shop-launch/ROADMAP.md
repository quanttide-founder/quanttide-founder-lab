# 开店助手路线图

可执行拆解与验收判据见 [TODO.md](TODO.md)。

把开店助手从「算账工具 + 能力边界框架」升级为一条完整的决策链：AI 按成文法判 → 人复核判例、修订条文 → 实测回填，最终沉淀可复用的「AI 能力 vs 现实」偏差地图（定义见 [AGENTS.md](AGENTS.md)）。检索引擎本轮不接入——开店语料小，直接读即可。

## 现状

- 能力边界框架：决策环节 × 输入依赖 A/B/C × 证据等级 L0/L1/L2（`AGENTS.md`）
- 算账工具：`src/ledger.py`（CLI，缺 L1 拒绝计算），只算 A 类
- 人机分工：**判例**（`data/能力对照表.csv`，八字段）与**成文法**（`AGENTS.md` 条文，`assess.py` 为投影）都显式存；AI 按成文法自主判决，人只做两层标注——判例复核（维持/改判）、法条修订（改条文重放）。逐条裁决的两版旧实现已废弃，反思见 `data/review/2026-09-28-裁决往返为何没用.md`
- 首例：滁州热锅串串，`data/火锅串串.md`，含 `[锁]/[L0]/[L1]` 三级参数与缺口

## Phase 2 — 做：人机对齐（判例与成文法）

具体决策（判例）与决策准则（成文法）都显式存，各配与之匹配的人工标注：判例层复核（便宜、抽查制）、法条层修订（贵、归纳制）。AI 按成文法自主判决，人不逐条拍板。机制定义见 `AGENTS.md`「人机对齐」，用法见 [docs/alignment.md](docs/alignment.md)。

- [x] 成文法条文带 § 编号（`标尺`、`检查§1–4`、`硬约束§n`），判例 `依据法条` 列可引用
- [x] 判例库显式化：`data/能力对照表.csv` 扩为八字段（+ 依据法条 + 复核），`assess.py` 自动填引用、`check` 校验、重放不覆盖已复核判例（改判终审）
- [x] 两种标注通道落文档与数据：`docs/alignment.md`、`data/纠偏记录.md`；删两版逐条裁决实现
- [x] 标注对象定形：`data/决策判例.csv`（AI 实质决策 16 条）+ `data/准则候选.csv`（隐含准则 10 条，互链）；元评估对照表降为背景
- [x] 判例复核 GUI（`src/review_gui.py`：决策维持/改判、准则采纳/否决，保存前两表互链校验，采纳自动渲染 `docs/决策准则.md`）；Label Studio 项目已删，外部标注平台出局
- [ ] ⏳ 实测一轮：抽查 → 判例改判 → 分诊 → 法条修订 → 重放，汇总**放大率**（一次修订覆盖的判例数 / 干预次数）
