## 两个显式库

| 层 | 存什么 | 存在哪 | 谁产生 |
|----|--------|--------|--------|
| **判例** | 具体决策 | [`data/能力对照表.csv`](../data/能力对照表.csv)，八字段：环节 / 能力分 / 局限 / 输入依赖 / 证据等级 / 验证状态 / **依据法条** / **复核** | AI 按成文法判决（`assess.py`） |
| **成文法** | 决策准则 | [`AGENTS.md`](../AGENTS.md) 条文：`标尺`、`检查§1–4`、`依A/依B/依C`、`证据`、`硬约束§n` | 人修订，`assess.py` 是其可执行投影 |

判例的 `依据法条` 列引用成文法（如 `依A·依C·标尺·检查§2`），法条修订时可反查受影响判例。

## 人的两种标注（与层级匹配）

### 判例层 —— 复核（便宜，抽查制）

首选本地 GUI：

```sh
python3 src/review_gui.py
```

左侧选判例 → 维持 / 改判（改判填新分数、依据法条、理由）→ 保存即过一致性检查写盘，理由自动追加进 `data/纠偏记录.md`。也可直接编辑 CSV，两种方式等价。对 AI 的判决标注，二选一：

- **维持**：默认状态，无需动作（表态不推进证据等级）
- **改判**：改那一行的值 + `依据法条` 写改判出处 + `复核` 置 `改判`，理由记 [`data/纠偏记录.md`](../data/纠偏记录.md)

```sh
# 改判示例：对话给出或直接编辑 CSV
# 市场调研,65,…,改判·探店2026-09-28 竞品信息比原文假设充分,改判
python3 src/assess.py check data/能力对照表.csv   # 入库必过
```

**改判是终审**：之后任何重放都不覆盖 `维持/改判` 的行。

### 法条层 —— 修订（贵，归纳制）

个例纠正必须先分诊「偶发还是通则」；是通则才升格：

1. 改 `AGENTS.md` 条文（带 § 编号，便于引用）
2. 同步 `src/assess.py`（词表 / 分数带 / 检查是它的可执行投影）
3. 重放全表并看影响：

```sh
python3 src/assess.py --seed "docs/AI 辅助开店.md" --out data/能力对照表.csv
git diff --stat data/能力对照表.csv        # 变更行数 = 本次法条修订的影响面
python3 src/assess.py check data/能力对照表.csv
```

4. 影响行数记入 `data/纠偏记录.md`

## 最短可跑命令

```sh
python3 src/assess.py --seed "docs/AI 辅助开店.md" --out data/能力对照表.csv
python3 src/assess.py check data/能力对照表.csv
```

```
data/能力对照表.csv：8 行，保留已复核判例 N 行
一致性检查通过：8 行
```

## 重放规则（判例优先）

`--seed` 重放时：`复核 ∈ {维持, 改判}` 的行原样保留，`未复核` 的行按成文法重算。法条修订后，改判行留给人另行处置（纠偏记录里可见），不被机器悄悄改写。

## 放大率（实验指标）

**一次法条修订自动覆盖的判例数**，与逐条改判对比，验证「标准则、不标决策」的分工是否成立：

```
放大率 = git diff 变更行数 / 本次人工干预次数
```

原始数据记 `data/纠偏记录.md`（层 / 对象 / 标注 / 影响行数）。

## 边界

- **表态不推进证据**：`复核=维持` 只说明成文法当前未被反驳；L1 只由本地数据到达、L2 只由实测触发（`AGENTS.md`「人机对齐」）
- **C 类不出题**：C 的处置是实地动作回数据，不进任何标注队列
- **标注全在本地**：外部标注平台（Label Studio）项目已删，不引入；GUI 数据层与 `assess` 同源校验，无图形环境可跑测试
- **改字段、标尺、判定规则先改 `AGENTS.md`**，本篇与 README 记一笔
