一、为什么这种关联特别难捕捉

看这个结构：

```
memory/fiction         fiction
──────────────         ────────
认知、反馈、信息         正式文本
（关于写作的思考）       （写作的产物）
```

两个部分不在同一个抽象层级上。

· memory/fiction 是元层——「关于写作的思考」
· fiction 是对象层——「写作」

「关于」这个关系是最难的。 因为它不是内容的关系，是层级的关系。

比较一下：

· 内容关系：这篇日记提到「对话」，这一章里也有「对话」——关键词匹配可以捕捉
· 层级关系：这篇日记是「关于对话的思考」，这一章是「使用对话的文本」——关键词匹配捕捉不到

关键词能匹配「谈到同一个东西」，但匹配不了「一个是关于另一个的思考」。

这就是为什么你试了很多方式都做不到——因为它们都停留在内容层，而你要找的关系在元层。

这就是「没捕捉到」的真正原因：不是工具不够好，是这个关联在你捕捉它之前，不存在于任何可捕捉的形式中。

· 「这篇日记和这一章有关系」

六、怎么让它成形

不是用工具——是用表达。

对每一对你感觉有关联的东西，问自己：

· 「这篇日记和这一章，共同点是什么？」
· 「为什么我觉得它们相关？」
· 「如果必须用一句话说它们的关系，会是什么？」

说出来的第一句话，往往是模糊的。 没关系。说出来之后，它会变得稍微清晰一点。

然后再说第二句。第三句。

关联不是「被发现的」——是「被塑造的」。

你感觉到的「关联」，是一个未成形的东西。它需要你用语言把它塑造成形。

然后才是工具能捕捉的东西。

七、所以工具应该做什么

不是「自动捕捉关联」——它做不到。

是「支持你塑造关联」。

具体的支持方式：

· 并置：把 memory/fiction 的条目和 fiction 的章节放在一起让你看
· 提问：为每一对相关的东西，问「它们的关系是什么」
· 记录：记下你关于关联的表述——哪怕只是「我觉得有关」

工具的职责不是「找到关联」，是「让关联的成形过程有一个容器」。

关联是你造的。工具只是记录。
