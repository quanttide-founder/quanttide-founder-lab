# 创作日志的收集与整理

将零散的创作日志收集、整理为主题日志与设定素材的流程。工作区是网络文学仓库的 `草稿箱` 目录（`1_创作日志`、`2_情绪日记`、`3_创作谈`、`4_创作设定`），整理成果按对应关系分流到各小说的工作流目录。

## 收集

1. 创作日志随手写入 `草稿箱/1_创作日志/`，一篇日志一个文件，可带系列前缀区分来源（如「职场言情-创作日志2.md」）；目录为空时不保留。
2. 情绪日记以情绪为单位写入 `草稿箱/2_情绪日记/`，而不是以时间为单位；情绪日记是母题的发现来源。
3. 小说专属的人设与母题素材直接放入对应小说的 `1_母题/`，不进入收集目录。

## 整理

1. 通读收集目录下的全部日志，逐篇按内容切分为条目。
2. 归并同主题条目，主题内部按创作脉络排序：早期困惑、中期洞察、后期转折。
3. 将条目组织为主题日志。保留作者原有的表达，仅补充必要的衔接，不重写原声。
4. 按对应关系分流整理成果：
   - 按主题归纳的创作日志（创作动机、创作方法、创作困境）放入 `草稿箱/3_创作谈/`；
   - 人物与世界观设定放入 `草稿箱/4_创作设定/`，按小说分文件；
   - 跨系列的世界观内容单独成篇，放入 `草稿箱/4_创作设定/三部曲世界观.md`；
   - 母题素材归入对应小说的 `1_母题/`。
5. 保留「未解的问题」类条目并集中标注，作为下一轮整理与创作的优先讨论对象。
6. 整理导致目录结构或流程变化时，同步更新网络文学仓库的 AGENTS.md。

## 提交

1. 子模块中的内容整理以「docs:」提交，目录与文件移动以「chore:」提交。
2. 先提交并推送子模块，再在主仓库以「chore: update fiction submodule」更新引用。
3. 提交前确认工作区只剩本次变更，原始日志删除后可从 Git 历史找回。
