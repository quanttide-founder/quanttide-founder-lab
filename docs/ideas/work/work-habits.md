# 作者的隐式工作习惯

基于 2026-03 至 2026-08 主仓库与子模块（memory/fiction/archive）的 Commit 历史、目录结构与 journal 内容归纳。标注为【证据】的条目可直接从仓库验证，【推断】为间接信号。

## 1. 知识管理：第二大脑式组织

- 【证据】主仓库 `quanttide-founder` 定位为"第二大脑"，以 Git 子模块分层管理：`apps/`（应用）、`assets/`（资产）、`examples/`（示例）、`.agents/skills/`（工作流封装）、`.quanttide/`（元信息）。
- 【证据】memory 子模块内部分层严格：`journal/`（每日流水）、`context/`（主题深度思考）、`roadmap/`（方向层）、`report/`（事实层）、`profile/`（个人资料）。
- 【证据】roadmap/report 边界规则被明文写入 AGENTS.md：决策归 roadmap，实现状态归 report。作者习惯把"想做什么"与"做到什么"分开记录。
- 【推断】目录即心智模型。作者通过目录结构管理认知负荷，结构调整（如 08-13 "把第二大脑从系统里分拆出来"）被当作情绪释放和创造自由的手段。

## 2. 记录习惯：每日 journal，小步频繁保存

- 【证据】`journal/YYYY-MM-DD.md` 每日一篇，连续无中断（07-29 至今）。
- 【证据】同一天内 journal 文件被多次提交（如 08-10 一日 6 次、08-09 一日 10 次），提交信息直接用文件名（如 "2026-08-14.md"），而非 Conventional Commits 格式。
- 【推断】journal 是"边写边存"的流式记录，不是收工后一次性整理。低摩擦提交优先级高于提交规范。
- 【证据】journal 内容固定混合：身体状况、情绪状态、当日进展、明日计划、自我分析。情绪记录占比高，作者习惯通过书写完成自我调节。

## 3. 提交习惯：高频小提交，类型收敛

- 【证据】主仓库绝大多数提交为 `chore: update X submodule`（子模块指针更新），其次 `docs`（CHANGELOG、报告、规范）。
- 【证据】`feat`/`fix`/`refactor` 极罕见，主仓库几乎不做代码开发——它是纯组织层。
- 【证据】带 scope 的格式出现过：`chore(qtfounder): update to site/v0.0.1`、`docs(report): ...`、`chore(auto-sync): ...`。
- 【证据】存在自动化同步机制（07-11 18:42/19:12 两条 `chore(auto-sync)`）。
- 【推断】作者将主仓库视为"变更流水账"，每次指针更新独立提交（原子提交原则），方便回溯任何子模块状态。

## 4. 发布习惯：版本契约化、集中发布

- 【证据】08-10 在 20 分钟内连续提交 8 次完成 v1.0.0 发布（submodule 更新 3 次 + changelog 2 次 + 文档 2 次），发布是"子模块先发、主仓库收尾"的批处理流程。
- 【证据】CHANGELOG 从 0.1.0 到 1.0.1 共 30+ 个版本，格式高度统一（Added/Changed/Removed/Fixed/Submodules 分节）。
- 【证据】版本契约明文规定：结构类变更为破坏性变更必须升 major，并在 CHANGELOG 写明迁移映射。
- 【推断】作者以版本号为项目节奏锚点，定期（约 1-2 周）打版；对"结构变动"的敬畏高于"内容新增"。

## 5. 时间节奏：夜型工作者

- 【证据】提交时间大量分布在 22:00-03:00（08-10 凌晨 00:55-03:39 连续 7 次提交；08-13 22:51/23:03；08-14 20:44）。
- 【证据】journal 常在深夜落笔（08-08 23:57、08-10 23:50、08-11 22:25）。
- 【推断】深夜是主要深度工作时间；午后（15:00-18:00）与傍晚是次要工作窗口。
- 【证据】journal 频繁记录身体疲劳与休息需求（"睡醒了又没睡饱""体力透支""腰酸"），作者在高强度输出后需要强制恢复期（版本冷却、断网休息是其在 context 中认可的机制）。

## 6. 工作偏好与自我认知

- 【证据】08-01 journal：明确"不爱写新功能，喜欢重构整理架构"，整理他人代码是其"舒适区"。
- 【证据】08-13 journal：主动拆分系统以求"自由创造"；07-30 起把数字化重担逐步交给团队/AI，目标是"脱离一线"。
- 【证据】journal 反复出现"把机制/规则显性化"的表述（影视规则、管理后台治理需求、经济建模思想）——作者习惯把隐性知识编码为文档、代码或 Skill。
- 【证据】08-09/08-10 journal 记录情绪波动（悲观→自我调节→乐观），并自我归因"压力大想放松""节奏慢慢找对"。
- 【推断】作者情绪自我觉察强，把状态波动当作系统信号处理，而非个人失败；倾向用"系统视角"（信息论、贝叶斯、吞吐量）描述自己的工作与情绪。

## 7. 与 AI 协作方式

- 【证据】context/ 下的文件（meta.md、ai-native-work.md、fiction.md、qtgame-war.md）是作者与 AI 深度对话后沉淀的思考，主题涵盖战略、创作、游戏设计。
- 【证据】ai-native-work.md 显示作者实践"AI 生成 + 人工审核 + 红队对抗 + 冷却期"的工作流，并主动提炼人机边界。
- 【证据】`.agents/skills/` 把高频流程（commit/release/submodule/review/deploy）封装为 Skill，且 AGENTS.md 维护"如何维护"索引。
- 【推断】作者把 AI 当作可编程协作者：规则先行（Skill/AGENTS.md），把重复劳动沉淀为流程，自己在"转弯处"把关。

## 对协作者的提示

1. 提交遵守 Conventional Commits，子模块更新用 `chore: update <name> submodule`，与既有历史保持同构。
2. 发布前先确认所有子模块引用最新；破坏性变更必须升 major 并写迁移映射。
3. journal 记录保持每日连续、内容私密化（情绪+进展+计划）的既有格式。
4. 作者偏好结构化分层文档（方向/事实分离），新内容先归位到对应层级。
5. 避免打断其夜间的深度工作窗口；高疲劳期适合安排整理型而非创新型任务。
